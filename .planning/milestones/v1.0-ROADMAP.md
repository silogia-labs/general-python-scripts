## Overview

Stdlib-only Python CLI that converts Quizify.io CSV exports into webhook-shaped JSON payloads matching `quizify-csv-to-json-webhook/docs/webhook-quizify-format-example.json`. Initial milestone delivers ingestion, classification, row mapping, scoring metadata, `quiz_title` precedence, and operator documentation.

## Phases

### Phase 1: CSV ingestion & column layout

**Goal**: Read exports deterministically and compute ordered question indices.
**Depends on**: Nothing (first phase)
**Requirements**: CONV-01, CONV-02
**Plans**: 1 plan

Plans:

- [x] 01: CSV ingestion + column layout (UTF-8-SIG read, header classification, `--dry-run`, `-v`, `--trailer-columns`)

**Details:**

- PII-safety baseline established: `--dry-run` stderr verified to contain no `@` (email markers) for the fixture.

### Phase 2: Core webhook mapping

**Goal**: Emit JSON objects per row matching baseline webhook keys and answer shapes.
**Depends on**: Phase 1
**Requirements**: CONV-03, CONV-04, CONV-05, CONV-06, WEB-01, WEB-02, WEB-03
**Plans**: 2 plans

Plans:

- [x] 02-01: Row builder + answer typing (CONV-03..06, WEB-01..03) with CLI JSON emission (TDD)
- [x] 02-02: Golden-file structural diff + sample-CSV invariants (verification harness)

**Details:**

- Pure-function pipeline: `decode_cell`, `shape_answer`, `map_status`, `match_tags_to_questions`, `build_row`, `convert`.
- `TAG_HEADER_MAP` constant routes per-row tags to specific question indices via NFC+casefold substring match (`red_flag` → `signos de alarma`, `goal_` → `objetivo`, `consent` → `consiento`).
- Answer shape heuristic: `", "` in cell → string; otherwise single-element object array with `answer_name`/`answer_img`/`answer_tag` and **no `id` key** (D-07 — omit unknown rather than guess).
- CLI surface: `-o`/`--output`, `--emit-json`, default JSON-to-stdout.
- PII-safety contract enforced by `tests/test_logging_pii.py`: warnings name columns and categorical values only (e.g. `'Subscribed to newsletter'`, `'no_pelvic_symptom'`), never cell content; verified by negative substring assertions for email/phone/free-text patterns.
- Verification harness: golden-file structural diff vs canonical example payload (id-stripped, Phase-3-stripped) + 12 invariants over the live 42-row sample using a module-scoped fixture (single CLI invocation; T-RESOURCE-01 mitigation).

### Phase 3: Scoring metadata & packaging

**Goal**: Finish scoring-related fields, quiz title handling, and operator docs.
**Depends on**: Phase 2
**Requirements**: WEB-04, WEB-05, OPS-01
**Plans**: 2 plans

Plans:

- [x] 03-01: Scoring + placeholder keys + `--quiz-title` precedence (TDD)
- [x] 03-02: Operator README (D-11 ten-section structure) + README↔`--help` drift smoke test

**Details:**

- `_resolve_quiz_title(args, environ)` private helper implements WEB-05 precedence: CLI flag > `$QUIZIFY_QUIZ_TITLE` env var > `""`. Decoded via `html.unescape` at the boundary; whitespace preserved.
- `SCORING_PLACEHOLDERS` module constant carries the 4 reserved keys (`product-recommendation: None`, `product-link-type: None`, `title: ""`, `type-page-url: ""`) in locked D-05 tail order.
- `build_row` now appends `quiz_title` at position 7 (D-05), three pass-through scoring keys (`result-logic`, `score-category`, `score-value` from `trailer_cells_decoded[0..2]`), then `row.update(SCORING_PLACEHOLDERS)`.
- `argparse` argument: `--quiz-title VALUE` with `default=None` (avoids env-capture-at-parser-build pitfall); env resolution happens post-parse.
- Operator README: 169 lines, 10 sections in D-11 order — Purpose / Quickstart / CLI reference / Configuration / Column assumptions / Output shape / Limitations / Privacy notes / Exit codes / Development.
- Drift smoke test (`tests/test_readme_help_alignment.py`): captures `--help` via subprocess, regex-extracts long-form flags, asserts each appears in `README.md`. Catches future flag additions without doc updates.

## Milestone Summary

**Decimal Phases:** None.

**Key Decisions:**

- D-01..D-15 (per-phase locked decisions in CONTEXT.md files) — implemented verbatim. Notable:
  - D-05: emitted top-level key order is a strict superset of the example payload (scoring trio added after dynamic question keys, before reserved placeholders).
  - D-07: `id` key never emitted in object-array answers (omit unknown rather than guess; diverges from example which sometimes carries `id`).
  - D-13: no `requirements.txt` shipped — runtime is stdlib-only; `requirements-dev.txt` exists for pytest tooling.
  - D-11: README structure locked at 10 sections; drift test enforces presence of section headings + every long-form CLI flag.
- TDD gate enforced for plans 02-01 and 03-01: RED commits (failing tests) precede GREEN commits (implementation).
- PII-safety posture (T-PII-01): warnings name columns + categorical enum values only; verified by negative substring assertions on stderr against email/phone/free-text patterns from the live sample.

**Issues Resolved:**

- Off-by-one in plan 02-01's expected `answers-tags-N` index for `consent_given` — live CSV places `Consiento` at q-20 while example payload places it at q-19; resolved by header-order-driven invariant test (not a hardcoded index) and a synthetic-aligned golden test for the example shape.
- Strict-equality test failure in `test_aligned_row_per_key_types_match_example` — example payload's `answers-3: "Ninguno"` is internally inconsistent (plain string while every other single-answer is an object array); resolved by carving out `answers-N` keys from strict type equality.
- Strict-equality test failure for `top_level_keyset` — D-05 explicitly emits the scoring trio as a *superset* of example shape; resolved by rewriting the test as superset-with-known-extras.
- Placeholder-value type divergence (`product-recommendation: null` vs example `"Basic"`) — resolved by adding a `placeholder_keys` carve-out to the per-key type test.

**Issues Deferred:**

- `--trailer-columns` non-default ordering can silently mis-bind scoring fields (RESEARCH Pitfall 3) — current implementation indexes scoring positions `[0..2]` of the trailer block. No INFO warning added (D-03: no new log surfaces in Phase 3). Deferred to v2 if a real export ever needs name-based scoring lookup.
- Streaming/NDJSON output for very large CSVs (T-RESOURCE-01) — current implementation accumulates rows in memory. Documented in `convert` docstring with threshold ~50k rows or >250MB.
- HTTP webhook POST mode (AUTO-01) — v2.
- JSON Schema validation against the example payload (VALI-01) — v2.

**Technical Debt Incurred:**

- None significant. Stdlib-only; no third-party packages introduced. Single-file implementation (`quizify_csv_ingest.py`, 427 lines) chosen over package layout because the surface is small and self-contained — split into a package only if v2 scope (HTTP POST, schema validation) lands.
